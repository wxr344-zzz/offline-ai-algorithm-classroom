# 双模型协同测试包：队友操作说明

此包为独立测试版：**Gemma 4 E4B（16K 上下文）生成原生 PPT 正文与讲解，Qwen2.5-Coder 7B 负责大纲、实验、测验与讨论**。它不替换你已有的单模型项目。

## 一、电脑准备

- Windows，Node.js 至少 22.19（本机验证版本 24.21.0）。
- Python 3.11，Ollama（本机验证版本 0.40.9）。先打开 Ollama。
- 安装 PostgreSQL，需包含 `initdb.exe`、`pg_ctl.exe`、`postgres.exe`；本机验证版本为 PostgreSQL 15。脚本会检测安装位置，检测不到时输入其 `bin` 文件夹路径。
- 本版在 8GB 显存机器上验证过。其他显卡的速度与显存分配需实测；两个模型按队列依次运行。

## 二、第一次准备，需要联网

1. 把压缩包解压到一个新的文件夹，**不要覆盖旧项目，不要在压缩包内部直接运行**。
2. 双击 **准备运行环境.cmd**。首次会安装前后端依赖、创建该目录专用数据库、下载缺少的两个模型、创建 Gemma 16K 标签，并构建网页。默认使用国内依赖镜像。
3. 看见 `READY` 再启动。若准备失败，先保存窗口报错，修正后重新运行；不要手动删除已有数据库。

若 PostgreSQL 没检测出来，可在解压后的项目目录打开普通 PowerShell，执行（按实际安装位置修改）：

```powershell
.\准备运行环境.cmd -PgBin "C:\Program Files\PostgreSQL\16\bin"
```

这次不使用旧版的 `-ContextLength 8192` 参数，也不要直接运行旧的 `scripts/offline/setup.ps1`。该包的通用“准备运行环境.cmd”已转到双模型准备入口。

## 三、启动与测试

1. 双击 **启动双模型协同测试版.cmd**。
2. 浏览器打开 **http://127.0.0.1:3200**，保留启动窗口。
3. 创建新课堂进行测试。关闭时按启动窗口的 Ctrl+C，或双击 **停止双模型测试版.cmd**。

首次准备完成后，可以断网测试文字生成、算法推演和编程实验。浏览器语音是否能离线使用取决于本机语音支持，断网时建议使用文字输入。

本副本使用网页 `3200`、Agent `8201`、模型队列 `11435`、独立数据库 `55433`。Ollama 仍使用本机 `11434`。不要同时让新旧两个版本生成课堂，以免争抢显卡。不要同时启动两份双模型测试包。

## 四、包内有什么

- 有：完整项目源码、专用准备/启动/停止脚本、公开双模型路由配置、已下载的浏览器运行资源。
- 没有：开发者的 `.env`、密钥、代理配置备份、数据库数据、历史课堂、日志、`node_modules`、`.venv`、`.next`。
- **不含模型权重**。准备脚本会下载缺少的 `qwen2.5-coder:7b`（约 4.7GB）与 `gemma4:e4b-it-qat`（约 6.1GB），已有的权重无需重复下载。16K 派生标签复用 Gemma 权重。

首次准备需要联网安装依赖与下载模型，因此这是一份可准备成离线环境的源码测试包，不是解压即用、完全无需联网的安装包。

数据库和服务密钥会在你电脑上随机生成；不用开发者的数据库密码，也不会改动你原有的 PostgreSQL 数据库。安装目录内的 `test-database` 是本副本数据，不要发送给别人。

## 五、建议反馈

用相同提示词、角色和 Lab 选项对比单模型版与双模型版。建议测二叉树遍历、队列及牛顿第二定律，记录：

- 完整提示词、角色选择、是否选择 Lab 和深度交互。
- 从开始到完成的总时间、是否发生失败或重试。
- PPT 的重复、知识错误、排版、讲解与页面是否一致。
- 讨论是否能回答，模拟器与公开测试是否正确。
- 显卡型号、显存、Ollama 版本及报错截图。

错误日志在 `logs`，发送前先检查是否包含自己的输入或本机信息。双模型方案的效果和速度需要比较测试，本包不保证对所有主题都优于单模型。
